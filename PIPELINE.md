# How this archive is built

Transcripts for the sermons on <https://www.youtube.com/@CanvasWinchester>,
transcribed locally with `whisper.cpp`.

`README.md` is generated by the pipeline — edit this file instead.

## Quick start

```bash
./run.sh                              # everything, resumable
python3 scripts/search.py "grace"     # search from the terminal
./site.sh serve                       # build the website, preview it
```

## Requirements

- `yt-dlp`, `ffmpeg`, `whisper-cli` (`brew install yt-dlp ffmpeg whisper-cpp`)
- A ggml Whisper model. Default: `~/models/ggml-large-v3-turbo.bin`
  ([download](https://huggingface.co/ggerganov/whisper.cpp)); override with
  `WHISPER_MODEL`.
- `claude` CLI for the optional summary stage.
- Node, for `npx pagefind` when building the website.

## Stages

| Stage | Script | What it does |
| --- | --- | --- |
| `index` | `fetch_index.py` | Lists every video on the channel into `data/index.json`. |
| `playlists` | `fetch_playlists.py` | Maps playlists onto videos and decides what counts as a sermon. |
| `transcribe` | `transcribe.py` | Downloads audio, runs Whisper, writes `data/whisper/<id>.json`. |
| `render` | `render.py` | Builds `transcripts/`, `text/`, `srt/` and `README.md`. |
| `summarize` | `summarize.py` | One summary per sermon via the `claude` CLI into `data/summaries/`. |
| `search` | `search.py` | Builds the SQLite FTS5 index at `data/search.db`. |
| — | `build_site.py` | Renders the static website into `docs/`. Run via `./site.sh`. |
| — | `analyze_series.py` | Reports series hiding among the un-playlisted sermons. Changes nothing. |

`render` runs twice in the default order: once to produce the text that
`summarize` reads, then again to fold the summaries back into the transcripts.

`captions` (`fetch_captions.py`) is optional. It pulls YouTube's auto-captions,
which are instant but lowercase and unpunctuated. Whisper output is preferred
whenever both exist. Useful only if you want something readable before a long
transcription run finishes.

## What counts as a sermon

238 of the channel's 249 videos. A video is a sermon if it is in one of the 37
sermon-series playlists, or — because ~45 sermons were never added to any
playlist — if its title is not a known non-sermon event.

Excluded: the two `C3 Connect` class playlists, `Testimonies`, Christmas Eve
services, `Night of Worship`, series "bumper" clips, announcements and the
Leadership Team Address. Full-service recordings (`Sunday @ Canvas ...`) are
**included**: they contain the sermon, and worship segments reduce to `[Music]`
cues that rendering drops.

Adjust the rules in `fetch_playlists.py` (`EXCLUDE_PLAYLIST`, `NON_SERMON_TITLE`)
and re-run `./run.sh playlists render`. Title rules deliberately outrank playlist
membership, because testimonies do turn up inside sermon playlists.

## Series that were never playlisted

"Standalone" mostly meant "nobody made a playlist" — 33 of the original 45 turned
out to belong to a series the church actually preached. `analyze_series.py` finds
them and, most usefully, quotes the announcement from the pulpit:

```bash
python3 scripts/analyze_series.py
```

Pass 0 greps the opening minutes for "our series through the book of ...", which
is first-hand evidence; the later passes (contiguous standalone runs, shared
scripture, title prefixes, neighbouring weeks) are inference and want a human eye.

Decisions live in `data/series_manual.json` (`{video_id: [series, ...]}`), merged
by `load_index()`. They cannot live in `data/index.json`: `fetch_playlists.py`
rebuilds `series` from the playlists on every run and would wipe them.

## Ingesting new sermons

```bash
./update.sh --dry-run    # poll and report, change nothing
./update.sh              # ingest what turned up, rebuild, commit
./update.sh --push       # ...and publish to GitHub Pages
```

Nothing about this is special-cased for "new": every stage already skips work it
has done, so `update.sh` is a thin wrapper that polls, decides whether anything
changed, and only then pays for the rest.

The gate is the SHA-256 of `data/index.json`. It changes when a video appears, when
an old sermon gains a series because someone finally made a playlist, and when a
date gets backfilled — all three want a rebuild. Unchanged means the run stops
before touching anything, which is the normal outcome most days. Verified against
the live channel: a full poll rewrites `index.json` byte-identically when nothing
has moved, so a daily schedule does not produce daily commits.

A no-op poll is `./run.sh index playlists` — two channel requests plus one per
playlist, about 40 for this channel, and one `fetch_meta` call per genuinely new
video. Cheap enough to run daily, far too expensive to run in a loop.

To schedule it on macOS, launchd survives reboots and skips missed runs while the
machine is asleep:

```bash
# ~/Library/LaunchAgents/church.transcripts.update.plist -> runs daily at 13:00
launchctl load -w ~/Library/LaunchAgents/church.transcripts.update.plist
```

GitHub Actions cannot do this job: transcription needs `whisper.cpp` and a 1.5 GB
local model, so the machine holding the model is the only place the pipeline runs.

Two things it deliberately does not do: it never deletes a sermon pulled from the
channel (the artifact in `data/whisper/` is the durable copy, and a video going
private should not silently empty the archive), and it does not push unless asked,
because pushing publishes.

## Output

```
transcripts/2024-03-18-a-living-savior-...-0kyMU8JXZL8.md   timestamps -> YouTube
text/2024-03-18-...txt                                      plain prose
srt/2024-03-18-...srt                                       subtitles
data/index.json        one record per video: title, date, duration, series, sermon flag
data/whisper/<id>.json raw Whisper output, the durable artifact
data/summaries/<id>.json  summary, key points, scriptures, themes
data/search.db         FTS5 index over paragraphs
```

Markdown front matter carries `series`, `themes` and `scriptures`, so the folder
drops into Obsidian or any static site generator as-is.

## Searching

```bash
python3 scripts/search.py "kingdom of God"           # phrase
python3 scripts/search.py "NEAR(grace faith, 6)"     # proximity
python3 scripts/search.py "fasting" --series JONAH    # filter by series
python3 scripts/search.py "prodigal" --json          # machine-readable
```

Hits resolve to a timestamped YouTube link, so you land on the moment itself.

## The website

```bash
./site.sh serve      # build, index, preview at localhost:8000
./site.sh            # build and index only
```

`build_site.py` renders `docs/` from the same artifacts everything else uses, so
it is disposable — the directory is wiped and rebuilt each run. 840 pages: one
per sermon, plus series, theme, scripture-book, timeline, and a full index.

Search is two layers:

- **Pagefind** over the whole archive. It only indexes the sermon transcripts,
  because they carry `data-pagefind-body` and that makes Pagefind skip every
  other page. The index is chunked, so a query downloads a few hundred KB rather
  than all 7.8 MB.
- **In-page finder** on each sermon. Search results link in with `?q=<term>`, so
  arriving from a search highlights every occurrence and dots the gutter
  timestamp beside each one. `f` focuses it, `n`/`N` step through hits.

Clicking any gutter timestamp seeks the embedded player. Each timestamp is also
a real link to YouTube, so it still works if the IFrame API is blocked.

### Assistants reading the site

`build_site.py` also writes `docs/llms.txt`, `robots.txt` and `sitemap.xml`.

`llms.txt` leads with provenance, because the failure it fixes was a trust
failure, not a parsing one: an assistant sent here by a link could not tell an
unofficial archive from an official one, and spent its effort deciding whether
the site was legitimate instead of answering. It now states plainly that this is
unofficial, that the church's channel is authoritative, that the sermons are
already public, and that the transcripts are unedited machine output — then
points at `text/<slug>.txt` as the preferred format. The same disclosure appears
in the footer of all 840 pages, since most arrivals land on a sermon, not the
index.

Set `SITE_BASE_URL` if the site moves; the absolute URLs in `llms.txt` and
`sitemap.xml` come from it.

`docs/` is laid out for GitHub Pages served from a branch's `/docs` folder. Links
are all relative and `.nojekyll` is written, so it works from a project subpath
(`/repo-name/`) without configuration.

## Notes and gotchas

- **`--print` implies `--simulate` in yt-dlp.** Combining it with
  `--write-auto-subs` silently downloads nothing. `--no-simulate` is required.
  This produced a convincing run in which every video appeared to have no
  captions.
- **Rate limiting is the main failure mode.** Six parallel workers got the IP
  bot-flagged within a couple of minutes. The scripts are serial with a delay,
  back off on HTTP 429, and stop after five consecutive blocks.
- **Never treat a failed request as "no captions."** `fetch_captions.py` records
  three states — has captions / confirmed none / unknown — and only an explicit
  yt-dlp message counts as confirmed. Unknowns get retried.
- Whisper runs about 30-50x realtime on an M3 Max with `large-v3-turbo`; the
  full 194 hours takes roughly 5-6 hours. Audio is deleted after each
  transcription, so peak disk use stays near one WAV.
- **Whisper loops a phrase over music and silence**, and it is not rare: 98 of
  the 238 sermons had a run of four or more identical consecutive segments, one
  of them repeating a single line 1,995 times. `collapse_loops()` in `common.py`
  keeps at most three in a row, which removed about 127,000 phantom words (7% of
  the archive). Genuine rhetorical repetition sits inside one segment, so it
  survives. Re-run `render`, `search` and `./site.sh` after changing the limit.
- **Whisper sometimes decodes a whole sermon uncased and unpunctuated** — 20 of
  the 238 here, tens of thousands of words with no sentence boundaries at all. It
  infers punctuation style from the text it thinks came before, so priming it
  fixes it: `--prompt` with a sentence in the register it is about to hear, plus
  `--carry-initial-prompt` so the priming repeats for every window instead of
  fading after the first thirty seconds. On one sermon that went from 2 sentences
  to 266, and 37 lowercase `i` to none.
  `unpunctuated()` in `common.py` is the detector and
  `transcribe.py --redo-unpunctuated` the fix; a re-run only replaces the
  original if it actually scores better.
- **Casing repair is not a substitute for re-transcribing.** `fix_caps()` raises
  proper nouns Whisper left lowercase (`god` → `God`, `holy spirit` → `Holy
  Spirit`, `john 3:16` → `John 3:16`) and never lowercases anything. It only
  fires on words that are proper nouns in every ordinary use, so `church`,
  `gospel`, `father`, `son` and `spirit` are left alone, and book names that
  double as English words (`job`, `mark`, `acts`, `numbers`) are capitalised only
  beside a chapter number or after "book/letter/gospel of". A good transcript has
  a couple of dozen of these; hundreds means the file was decoded uncased and
  wants `--redo-unpunctuated` instead.
- **Every word added to `PROPER` is a bet, and some lose.** `Lent` capitalised
  "no one would have lent him this much money"; `Advent` capitalised "the advent
  of machinery and electricity"; `Gospels` capitalised "false gospels", which
  means a counterfeit message, not the four books. Before adding a word, count
  how often Whisper already gets it right (`data/whisper/` is the pre-`fix_caps`
  text) and read the contexts where it doesn't — a wrong capital reads worse than
  a missing one. `fix_caps` runs over summaries too, via `load_summary()`, so the
  theme pages on the website are where a bad entry shows up first.
- `render.py` also flags any transcript under 200 words as suspicious. To find
  the opposite problem — transcription stopping early — compare the last cue's
  end against the video duration; one sermon covers only 60% because the
  recording has a long dead tail.
- Transcripts are unedited machine output and will contain errors, especially in
  proper nouns and scripture references. Treat summaries as a finding aid, not a
  citation, and check the audio before quoting anything publicly.
